## 한 줄 정의

계획을 한 번에 다 세우지 않고 **짧은 주기로 만들고 고치기**를 반복하는 개발 방식.

## 비유

코스 요리를 다 만든 뒤 한꺼번에 내는 대신 **한 접시씩 내고 손님 반응을 보며** 다음 접시를 정하는 식당. 스크럼은 그 식당의 "2주에 한 접시, 매일 아침 5분 회의" 같은 정해진 진행 규칙이다.

## 예시

연구실 툴 개발을 2주 스프린트로 돌리면 이렇게 된다.

```text
스프린트 1 (9/25 ~ 10/8)
  목표     : Devpedia 카드 30장 + 검색이 동작하는 상태
  백로그   : 카드 작성 / 검색 / 카테고리 탭 / PWA (이번엔 안 함)
  데일리   : 매일 10:00, 어제 한 것 · 오늘 할 것 · 막힌 것 — 5분
  리뷰     : 10/8 돌아가는 화면을 교수님께 시연
  회고     : 잘 된 것 · 안 된 것 · 다음 스프린트에서 바꿀 것 하나
```

스크럼 용어는 네 개만 알면 된다 — 스프린트(짧은 개발 주기, 보통 1~4주), 백로그(우선순위 매긴 할 일 목록), 데일리 스크럼(짧은 아침 회의), 회고. 졸업 프로젝트에서 "매주 금요일에 돌아가는 걸 보여준다"만 지켜도 절반은 애자일이다.

## 헷갈리기 쉬운 것

- **워터폴(폭포수)**은 요구 분석 → 설계 → 구현 → 테스트를 한 번씩 순서대로 끝내는 방식. 뒤에 가서 요구가 바뀌면 되돌아가는 비용이 크다.
- **애자일**은 사고방식(짧게 만들고 자주 보여주자)이고 **스크럼**은 그것을 실천하는 구체적 규칙 묶음 중 하나. 칸반(보드로 흐름 관리)도 또 다른 실천법.
