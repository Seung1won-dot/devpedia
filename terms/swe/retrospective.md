## 한 줄 정의

한 주기가 끝날 때 팀이 모여 **잘된 것·안 된 것·다음에 바꿀 것**을 정리하는 자리.

## 비유

시험이 끝난 뒤 쓰는 **오답 노트**. 점수를 탓하는 게 아니라 "다음 시험엔 뭘 다르게 할까" 한 가지를 적어 두는 것이다.

## 예시

```text
스프린트 3 회고 (10/8, 30분) — KPT
Keep    : 매일 10시 데일리 5분 — 막힌 것을 당일에 풀었다
Problem : GPU 서버 예약이 겹쳐 학습이 두 번 중단됨
          PR 리뷰가 평균 3일 걸림
Try     : GPU 예약 캘린더 하나 만들기            (담당 민수, 10/10 까지)
          PR 올리면 Slack 채널에 자동 알림        (담당 지영, 10/12 까지)
```

형식은 KPT(Keep·Problem·Try)면 충분하다. 지킬 규칙은 세 가지 — **사람이 아니라 과정을 탓한다**, Try 는 한두 개로 좁혀 담당과 기한을 붙인다, 다음 회고의 첫 순서는 "지난 Try 가 실행됐나" 확인이다. 30분을 넘기면 불평 모임이 되니 타이머를 켠다. 연구실에서는 스프린트가 없어도 학기 말·논문 제출 직후·학회 발표 뒤에 한 번씩 하면 같은 실수가 다음 학기에 반복되는 걸 막는다.

## 헷갈리기 쉬운 것

- **스프린트 리뷰**는 만든 **결과물**을 교수님·사용자에게 보여 주는 자리, 회고는 **일하는 방식**을 팀끼리 돌아보는 자리다. 보통 리뷰 직후에 회고를 한다.
- **포스트모템**은 장애 같은 특정 사건 하나를 파고드는 사후 분석. 회고는 사건이 없어도 주기적으로 한다.
- **반성문**이 아니다. 누가 잘못했는지 찾기 시작하면 다음부터 아무도 문제를 말하지 않는다.
