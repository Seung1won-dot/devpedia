## 한 줄 정의

테스트가 없어 **고치기 무섭지만 지금도 잘 돌아가고 있는** 물려받은 코드.

## 비유

할머니 집의 **낡은 전기 배선**. 어느 선이 어디로 가는지 아무도 모르지만 불은 잘 들어오니, 함부로 뜯기 전에 회로도부터 그려야 한다.

## 예시

```python
# 1) 지금 동작을 그대로 '박제'하는 테스트부터 — 맞는지는 묻지 않는다 (특성화 테스트)
def test_parse_patient_as_is():
    msg = open("fixtures/adt_a01_2019.hl7", encoding="cp949").read()
    assert parse_patient(msg) == {"mrn": "00012345", "sex": "F", "birth": "19570302"}

# 2) 테스트가 초록이면 그제야 안쪽을 조금씩 리팩토링한다
# 3) 새 기능은 레거시를 감싸는 얇은 층에 붙이고, 옛 코드는 한 조각씩 바꿔 나간다
```

연구실에서는 졸업한 선배가 남긴 HL7 파서, 10년 된 HIS 연동 스크립트가 대표다. 순서는 **먼저 테스트로 현재 동작을 고정하고, 그다음 고친다** — 그래서 "레거시 코드 = 테스트 없는 코드"라는 정의가 널리 쓰인다. "다 갈아엎자"는 대개 실패하는데, 이상해 보이는 분기 안에 병원 특수 케이스가 묻혀 있기 때문이다. 트레이드오프: 안 건드리면 안전하지만 기능 하나 붙일 때마다 비용이 오르고, 테스트를 깔아 두는 데는 당장 시간이 든다. 새 코드로 옛 코드를 조금씩 둘러싸 교체하는 방식을 **교살자 패턴**(strangler fig) 이라 부른다.

## 헷갈리기 쉬운 것

- **기술 부채**는 알면서 미룬 것이라 장부가 있다. 레거시는 왜 그런지 아무도 모르는 채 물려받은 것까지 포함한다 — 장부가 없다.
- **구버전 기술**이라고 다 레거시는 아니다. Python 2 라도 테스트가 있고 읽히면 그냥 오래된 코드고, 어제 짠 코드라도 테스트가 없으면 레거시다.
- **리팩토링**은 레거시를 다루는 수단. 테스트 없이 하는 리팩토링은 리팩토링이 아니라 그냥 위험한 수정이다.
