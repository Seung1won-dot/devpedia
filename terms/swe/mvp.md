## 한 줄 정의

핵심 기능만 담은 **가장 작은 버전**을 먼저 내놓고 반응을 보며 키우는 제품.

## 비유

카페를 차리기 전에 **노점에서 커피 한 종류만** 팔아보는 것. 사람들이 사 가면 그때 가게를 넓히고, 안 팔리면 인테리어에 돈을 쓰기 전에 알 수 있다.

## 예시

```text
Devpedia v0.1 (MVP)
  ✓ 카드 Markdown 파일 → 빌드 → 정적 페이지 하나
  ✓ 카테고리 탭 + 제목·별칭 검색
  ✗ 오프라인(PWA), 즐겨찾기, 통계 화면 — 연구실 사람들이 실제로 쓰는지 본 뒤에
```

카드 10장으로 먼저 배포해서 "세미나 중에 진짜 열어보나?"를 확인하고, 그 다음에 기능을 붙인다. 논문 코드 데모도 같다 — 웹 UI 를 꾸미기 전에 명령 한 줄로 결과가 나오는 스크립트부터 공개해 반응을 본다.

## 헷갈리기 쉬운 것

- **프로토타입**은 "만들 수 있나, 어떻게 보이나"를 확인하는 시제품이라 버려도 된다. MVP 는 실제 사용자에게 내놓는 진짜 제품의 첫 버전.
- **기능을 대충 만든 것**과 다르다. 기능 수는 최소지만 그 하나는 제대로 동작해야 한다.
