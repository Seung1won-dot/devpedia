## 한 줄 정의

할 일을 **보드의 열로 옮기며** 동시에 진행하는 일 수를 제한하는 흐름 관리 방식.

## 비유

식당 주방의 **주문표 걸이**. 들어온 주문을 왼쪽에 걸고 요리가 끝나면 오른쪽으로 옮기는데, 걸이에 자리가 다 차면 새 주문을 받지 않고 밀린 것부터 끝낸다.

## 예시

```text
Todo (백로그)              Doing (WIP 2)            Review              Done
------------------------  ----------------------  ------------------  ------------------
#31 DICOM 익명화 스크립트    #28 FHIR 파서 테스트      #27 README 갱신      #25 pgvector 세팅
#32 IRB 서류 양식           #30 로그인 만료 버그                           #24 Caddy HTTPS
#33 대시보드 다크 모드
```

GitHub Projects 보드를 열면 이 그림이 그대로 나온다. 칸반이 "열 세 개짜리 보드" 와 다른 점은 두 가지다. 첫째, **WIP(진행 중) 제한** — Doing 열에 2장을 넘기지 않고, 하나를 Done 으로 보내야 다음 카드를 꺼낸다. 둘째, **쌓이는 열이 병목** — Review 에 카드가 밀리면 리뷰어가 부족하다는 뜻이니 코드를 더 짜는 대신 리뷰부터 한다. 논문·코드·IRB 서류가 섞여 2주 단위로 자르기 어려운 연구실 일에는 스프린트보다 칸반이 잘 맞는다.

## 헷갈리기 쉬운 것

- **스크럼**은 스프린트라는 고정 주기와 역할(PO·스크럼 마스터)이 정해져 있다. 칸반은 주기 없이 카드가 들어오는 대로 흘려보내고 역할도 규정하지 않는다. 둘을 섞은 "스크럼반" 도 흔하다.
- **To-do 보드**: 열을 그려 놓기만 한 것은 칸반이 아니다. WIP 제한과 "어느 열에 쌓이나" 를 보는 습관이 있어야 칸반이다.
- **백로그**는 보드 맨 왼쪽(또는 보드 밖)의 우선순위 매긴 대기 목록. 칸반은 그 목록을 꺼내 흘려보내는 방식이다.
