## 한 줄 정의

**UX**는 제품을 쓰는 동안의 경험 전체, **UI**는 그 경험이 닿는 화면과 조작 요소다.

## 비유

식당으로 치면 UI 는 **메뉴판·의자·식기**, UX 는 예약부터 계산하고 나올 때까지의 **기분 전체**다. 메뉴판이 예뻐도 주문이 30분 걸리면 UX 는 나쁘다.

## 예시

Devpedia 에서 "검색창 모서리를 둥글게, 앰버색 포커스 테두리" 는 UI 결정이다. "용어를 몰라도 카테고리 → 태그로 좁혀 들어가 10초 안에 카드를 찾게 한다" 는 UX 목표다. 개발자가 디자이너와 일할 때 UI 시안은 Figma 로 받지만, UX 쪽 질문("이 화면에 오기 전에 사용자는 뭘 했나?", "실패하면 어디로 가나?")은 개발자가 먼저 던져야 빈 상태·에러 화면이 빠지지 않는다.

## 헷갈리기 쉬운 것

- **UX 디자이너 vs UI 디자이너**: 앞쪽은 조사·흐름·구조, 뒤쪽은 색·글꼴·컴포넌트를 주로 맡는다. 작은 팀에서는 한 사람이 둘 다 한다.
- **UI vs 프론트엔드**: UI 는 "어떻게 보이고 반응해야 하는가" 의 설계, 프론트엔드는 그것을 코드로 구현하는 일이다.
