## 한 줄 정의

정해진 시간 안에 **알고리즘 문제를 코드로 풀어** 통과 여부를 가리는 채용 시험.

## 비유

운전면허 기능시험. 실제 도로(실무)와는 다르지만, 기본 조작(자료구조·알고리즘)이 몸에 붙었는지를 짧은 시간에 거르는 관문이다.

## 예시

```text
형식      온라인 응시(프로그래머스·코드시그널·해커랭크 등), 자택, 웹캠·화면 녹화
문제 수   2~5문제, 앞쪽이 쉽고 뒤로 갈수록 어려운 배치가 많다
시간      2~4시간
언어      대부분 자유(Python·Java·C++·JS), 일부 기업은 제한 [확인 필요]
통과선    "5문제 중 3~4개" 식의 소문은 많지만 기업·시즌마다 다르다 [확인 필요]
감독      웹캠·화면 공유 녹화, 복사·붙여넣기 감지, 제출 코드 유사도 검사
```

3시간 4문제라면 시간 배분은 이런 식이다.

```text
0:00  네 문제 다 읽고 쉬운 순서 정하기 (5~10분) — 1번이 제일 쉽다는 보장 없음
0:10  구현 문제 → 20~30분, 예제 통과 후 내가 만든 엣지 케이스(빈 입력, 최대 n) 확인
0:40  탐색 문제 → BFS/완전탐색, 제출 전 시간 복잡도 계산 (n=10^5 에 O(n²) 이면 다시)
1:40  DP/이분탐색 → 못 풀겠으면 부분 점수를 노리고 브루트포스라도 제출
2:40  제출 코드 다시 훑기 — 디버그 print 삭제, 입력 형식 재확인
```

부정행위 규정은 시험마다 다르다. 검색을 허용하는 곳, IDE 자동완성까지 막는 곳, AI 도구 사용을 명시적으로 금지하는 곳이 섞여 있으니 안내 메일을 끝까지 읽는다. 코테는 붙이는 시험이 아니라 떨어뜨리는 관문이라서, 화려한 알고리즘보다 "구현·탐색을 실수 없이" 가 통과의 핵심이다. 코테를 통과한 뒤 기술면접에서 "3번 문제 어떻게 푸셨어요?" 하고 묻는 회사도 있으니 시험 직후 풀이를 복기해 둔다.

## 헷갈리기 쉬운 것

- **라이브 코딩**은 면접관 앞에서 실시간으로 짜는 것. 코테는 혼자 온라인으로 결과만 낸다.
- **과제 전형**은 며칠 동안 실제 기능을 구현해 제출. 코테는 몇 시간 안에 알고리즘 문제.
- **삼성 SW 역량테스트**도 코테의 일종이지만 오프라인·구현 위주라 따로 준비한다.
