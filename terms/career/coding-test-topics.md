## 한 줄 정의

국내 코테에 **자주 나오는 문제 유형**을 우선순위대로 정리한 것.

## 비유

수능 기출 유형 분석. 전 범위를 다 파기 전에 **매년 나오는 단원**부터 확실히 잡는다.

## 예시

```text
우선  유형            한 줄                                              관련 카드
1    구현·시뮬레이션   문제 조건을 빠짐없이 코드로 옮기기, 2차원 배열·방향 배열    array
2    완전탐색         모든 경우를 다 해 보기, 연산 1억 번 이하면 가능             recursion, backtracking
3    BFS/DFS         격자·그래프 탐색, 최단 거리는 BFS·연결 요소는 DFS           bfs-dfs, graph
4    정렬 + 해시      일단 정렬해 놓고 생각하기, 개수 세기는 딕셔너리             sorting, hash-table
5    이분탐색         "최댓값의 최솟값" 류, 답의 범위를 반씩 줄이기               binary-search
6    DP              작은 문제의 답을 저장해 큰 문제 풀기, 점화식 세우기          dynamic-programming
7    그리디           매 순간 최선이 전체 최선임을 확신할 수 있을 때             greedy
8    문자열·투 포인터  파싱, 슬라이딩 윈도우, 두 포인터로 O(n)                   two-pointers, regex
9    스택/큐/힙       괄호 짝, 다음 큰 수, 우선순위 처리                        stack-queue, heap
```

1~4번만 확실해도 국내 코테 문제의 절반 이상에 손을 댈 수 있다는 게 통설이다 [확인 필요]. 트리·다익스트라·유니온파인드·위상정렬은 그다음이고, 카카오처럼 난도가 높은 곳을 노릴 때 추가한다 [확인 필요]. 문제를 읽고 유형을 고르는 신호는 입력 크기다.

```text
n ≤ 20          완전탐색·비트마스크 (2^20 ≈ 100만)
n ≤ 5,000       O(n²) 허용 — 이중 반복, 간단한 DP
n ≤ 100,000     O(n log n) — 정렬, 이분탐색, 투 포인터, 힙
n ≥ 1,000,000   O(n) 또는 O(1) — 해시, 누적합, 수식
"격자 + 최단"  BFS   /   "최댓값의 최솟값"  이분탐색   /   "경우의 수·최대 합"  DP
```

기술면접에서는 코테 유형이 그대로 비교 질문이 된다 — "BFS 와 DFS 는 언제 뭘 쓰나요?", "DP 와 분할정복 차이는요?", "그리디가 항상 최적이 아닌 예를 들어 보세요." 유형별로 대표 문제 3개씩 손에 익혀 두면 시험과 면접 둘 다 커버된다.

## 헷갈리기 쉬운 것

- **완전탐색과 백트래킹**: 백트래킹은 완전탐색에 "가망 없으면 되돌아가기" 가지치기를 붙인 것.
- **DP 와 그리디**: 둘 다 최적화 문제. 현재 최선이 전체 최선임이 보장되면 그리디, 아니면 DP 로 모든 선택을 저장한다.
- **BFS 와 다익스트라**: 간선 가중치가 없거나 모두 같으면 BFS, 다르면 다익스트라.
