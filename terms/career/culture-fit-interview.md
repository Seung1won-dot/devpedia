## 한 줄 정의

회사의 **일하는 방식·가치관과 내가 맞는지** 서로 확인하는 면접.

## 비유

룸메이트 구하기 면담. 요리 실력(기술)보다 **생활 습관이 맞는지**를 본다 — 밤샘형과 아침형이 같이 살면 둘 다 괴롭다.

## 예시

```text
자주 나오는 질문
- 팀 프로젝트에서 의견이 부딪혔던 경험과 어떻게 풀었는지 말해 주세요.
- 실패한 프로젝트가 있나요? 거기서 무엇을 배웠나요?
- 코드 리뷰에서 내 코드에 반대 의견이 달리면 어떻게 하나요?
- 마감은 촉박한데 품질이 부족하면 무엇을 포기하나요?
- 우리 서비스 써 보셨나요? 불편한 점 하나만 말해 주세요.
```

경험 질문은 STAR 로 답한다. 상황(Situation) → 과제(Task) → 행동(Action) → 결과(Result).

```text
S  졸업 프로젝트 4명, 발표 2주 전에 백엔드 API 응답 형식이 두 번 바뀜
T  프론트 담당인 내가 매번 다시 짜야 했고, 팀 채팅 분위기가 나빠짐
A  탓하는 대신 "변경은 이슈로 남기고 하루 한 번만 반영" 을 제안,
   요청·응답 예시를 README 에 고정해 둘 다 그것을 기준으로 작업
R  변경 3회 → 1회로 줄고 발표 일정을 지킴. 이후 프로젝트는 API 문서를 먼저 쓴다
```

포인트는 "내가 옳았다" 가 아니라 **상대 입장을 이해하고 규칙으로 풀었다**는 것이다. 실패 질문은 실패 인정 + 배운 것 + 그 뒤 바뀐 행동, 세 가지가 다 들어가야 하고 "실패한 적 없다" 가 제일 나쁜 답이다. 지원 전에 회사 홈페이지·채용 공고·기술 블로그에서 그 회사가 자율과 관리, 속도와 안정 중 어느 쪽을 강조하는지 읽어 두면 질문의 의도가 보인다. 이 면접은 나도 회사를 고르는 자리라서 "팀의 코드 리뷰 문화는 어떤가요?" 같은 역질문을 두 개쯤 준비해 간다.

## 헷갈리기 쉬운 것

- **인성면접**은 성실성·태도 같은 일반적 인성을 본다. 컬처핏은 "이 회사 방식" 과의 궁합이고, 스타트업·IT 기업이 주로 이 이름을 쓴다. 실제로는 섞여서 진행되는 경우가 많다.
- **임원면접**은 임원이 최종 확인하는 자리. 지원 동기와 회사 이해도 비중이 크다.
- **기술면접**은 지식·경험의 깊이. 컬처핏에서 기술 질문이 나오면 답보다 "모를 때 어떻게 말하나" 를 본다.
