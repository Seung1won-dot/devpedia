## 한 줄 정의

면접관이 보는 앞에서 **생각을 말하며 실시간으로 코드를 짜는** 면접.

## 비유

요리 경연의 라이브 미션. 완성된 접시도 보지만, **재료를 고르고 순서를 정하는 과정**을 심사위원이 옆에서 지켜본다.

## 예시

```text
면접관: 문자열 배열에서 서로 애너그램인 것끼리 묶어 주세요.
나    : 몇 가지 확인할게요. 빈 배열이 올 수 있나요? 대소문자를 구분하나요? 단어 길이 상한은요?
면접관: 소문자 영어만, 빈 배열은 없다고 보셔도 됩니다.
나    : 각 단어를 정렬한 문자열을 키로 해시맵에 모으겠습니다. 단어 n개, 길이 k면
        O(n·k log k) 입니다. 이걸로 먼저 짜고, 시간이 남으면 알파벳 26칸 카운트를
        키로 써서 O(n·k) 로 줄이겠습니다. 이 방향 괜찮을까요?
면접관: 네, 진행하세요.  (코드 작성 5분 — 한 줄 쓸 때마다 "여기서 키를 만들고요" 식으로 설명)
나    : ["eat","tea","tan"] 으로 손으로 따라가 볼게요. eat → "aet" … 결과가 두 그룹입니다.
```

순서를 외워 두면 긴장해도 몸이 움직인다.

```text
1. 요구사항·예외 케이스 먼저 묻기 (입력 범위, 빈 값, 중복, 정렬 여부)
2. 접근법 + 시간 복잡도를 말하고 "이 방향 괜찮을까요?" 동의 받고 시작
3. 짜는 동안 소리 내어 생각하기 — 침묵 30초가 제일 나쁘다
4. 다 짜면 작은 예제로 손 추적(dry run), 엣지 케이스 하나 더
5. 막히면: "지금 X 까지 됐고 Y 에서 막혔는데, 일단 O(n²) 으로 가도 될까요?"
```

면접관은 정답 여부보다 **막혔을 때 어떻게 움직이나**를 본다. 힌트를 주면 감점이 아니라 "힌트를 받아 나아가는가" 를 보는 것이니 바로 받아들여 적용한다. 변수 이름은 `a`, `b` 대신 `word_groups` 처럼 읽히게 — 옆에서 보는 사람이 있다는 걸 잊지 않는다. 연습은 혼자 문제를 풀 때 실제로 입 밖에 내어 설명하면서 푸는 것으로 충분하다.

## 헷갈리기 쉬운 것

- **코딩테스트**는 혼자 풀고 결과만 채점. 라이브 코딩은 과정과 소통이 점수다.
- **페어 프로그래밍 면접**은 면접관이 같이 짜거나 리뷰하며 진행하는 변형. 대화가 더 많다.
- **화이트보드 코딩**은 종이·보드에 손으로 쓴다. 문법 오류보다 로직과 설명이 중요하다.
