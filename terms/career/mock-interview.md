## 한 줄 정의

실제 면접처럼 **소리 내어 답해 보며** 아는 것과 말할 수 있는 것의 차이를 메우는 연습.

## 비유

수영 교본을 다 읽어도 물에 들어가면 가라앉는다. 모의 면접은 얕은 물에서 먼저 허우적대 보는 것이다.

## 예시

혼자 → 녹화 → 스터디, 세 단계로 올린다.

```text
1단계 혼자 (매일 10분)
  이 사전에서 카드 하나를 무작위로 연다 → 화면을 덮고
  "정의 → 왜 필요한가 → 장단점·비교" 로 1분 말한다 → 폰으로 녹음
  → 다시 들으며 카드와 비교: 빠진 것, "어…" 횟수, 1분 넘겼는지
2단계 녹화 (주 1회)
  CS 3문항 + 프로젝트 2문항을 카메라 켜고 답한다. 시선·속도·말버릇 확인
3단계 스터디 (주 1회, 3~4명)
  면접관 역할을 돌아가며 맡고, 규칙 하나: 모든 답변에 반드시 "왜요?" 를 한 번 더 묻는다
```

질문 리스트는 직접 만든다. 과목별로 15~20개, 각 질문에 꼬리 질문 하나씩.

| 과목 | 1분 질문 | 꼬리 질문 |
| --- | --- | --- |
| OS | 프로세스와 스레드의 차이는? | 그럼 멀티스레드가 항상 빠른가요? |
| 네트워크 | TCP 와 UDP 의 차이는? | 화상 통화는 왜 UDP 를 쓰나요? |
| DB | 인덱스란? | 인덱스를 많이 만들면 왜 안 되나요? |
| 프로젝트 | 가장 어려웠던 문제는? | 그때 다른 방법은 없었나요? |

피드백은 네 칸만 본다 — 첫 문장이 정의(결론)였나, 1분 안에 끝났나, 모르는 건 "정확히는 모르지만 ~로 추측합니다" 로 답했나, 프로젝트 답에 숫자와 도구 이름이 있었나. 서류 합격부터 면접까지는 보통 1~3주라 그때 시작하면 늦다. 1단계는 4학년 1학기부터 습관으로 두고, 2·3단계는 지원 시즌에 붙인다.

혼자 할 때 가장 흔한 착각은 "읽어 보니 아는 내용이네" 다. 말로 뱉어 보면 첫 문장에서 막힌다. 그 차이를 확인하는 것 자체가 모의 면접의 목적이다.

## 헷갈리기 쉬운 것

- **답 외우기**와 다르다. 문장을 통째로 외우면 꼬리 질문에서 바로 무너진다. 뼈대(정의·왜·장단점)만 고정하고 살은 매번 다르게 붙인다.
- **코딩 테스트 연습**(백준)과 별개다. 라이브 코딩 대비는 "생각을 말하면서 코드 쓰기" 라 또 다른 연습이 필요하다.
- **인성 면접**도 모의가 필요하다. 지원 동기·갈등 경험·실패 경험은 기술 답변과 구조(STAR)가 다르다.
