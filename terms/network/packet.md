## 한 줄 정의

데이터를 네트워크로 보낼 때 **받는 주소를 붙여 잘게 쪼갠** 전송의 기본 단위.

## 비유

긴 편지를 **엽서 여러 장**에 나눠 적고, 장마다 받는 주소와 "3/12" 같은 번호를 붙여 보내는 것. 엽서가 제각각 다른 길로 가도 받는 쪽에서 번호대로 다시 맞추면 원래 편지가 된다.

## 예시

```bash
sudo tcpdump -i any -n -c 3 port 11434
# 14:02:11.482913 IP 192.168.10.5.52310 > 192.168.10.20.11434: Flags [P.], seq 1:88, ack 1, length 87
# 14:02:11.483401 IP 192.168.10.20.11434 > 192.168.10.5.52310: Flags [.], ack 88, length 0
```

한 줄이 패킷 하나다. 앞부분이 **헤더**(보낸 곳·받는 곳의 IP 와 포트, 순서 번호), `length 87` 이 실제 내용(**페이로드**)의 크기. 이더넷에서는 패킷 하나가 보통 1500바이트를 넘지 못하므로, 100MB 짜리 DICOM 파일을 `scp` 로 옮기면 7만 개 가까운 패킷으로 쪼개져 날아가고 받는 쪽 TCP 가 순서를 맞춰 다시 붙인다. 화면으로 뜯어보고 싶으면 Wireshark 가 같은 일을 GUI 로 보여 준다.

## 헷갈리기 쉬운 것

- 계층마다 이름이 다르다: 이더넷(2계층)에서는 **프레임**, IP(3계층)에서는 **패킷**, TCP(4계층)에서는 **세그먼트**, UDP 는 **데이터그램**. 같은 데이터에 봉투가 한 겹씩 더 싸인 것이라 일상에선 뭉뚱그려 패킷이라 부른다.
- **패킷 손실**은 조각 하나가 중간에서 사라진 것. TCP 는 다시 보내 달라고 하지만 UDP 는 그냥 넘어가므로, 영상 통화가 잠깐 깨지는 게 이것이다.
- **MTU** 는 패킷 하나의 크기 한도이지 패킷 그 자체가 아니다.
