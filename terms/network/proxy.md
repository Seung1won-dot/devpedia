## 한 줄 정의

클라이언트 **대신 바깥 서버에 요청을 보내 주는** 중계 서버.

## 비유

내 대신 가게에 다녀오는 **심부름꾼**. 가게 주인은 심부름꾼 얼굴만 보고(익명화), 심부름꾼은 자주 사는 물건을 미리 쟁여 두며(캐시), 부모님이 "과자는 사 오지 마" 라고 심부름꾼에게 일러둘 수도 있다(접근 제어).

## 예시

```bash
# 연구실 폐쇄망 VM: 인터넷은 프록시 서버(192.168.10.5:3128)를 통해서만 나간다
export HTTPS_PROXY=http://192.168.10.5:3128
curl -I https://pypi.org/simple/                      # 프록시가 대신 받아 와서 돌려준다
pip download numpy --proxy http://192.168.10.5:3128
# 개발 중에는 mitmproxy 를 프록시로 두고 앱이 실제로 뭘 보내는지 들여다본다
mitmproxy --listen-port 8080
```

의료 IT 연구실처럼 환자 데이터가 있는 망은 VM 이 인터넷에 직접 못 나가게 막고, 허용된 도메인만 통과시키는 프록시(Squid 등) 하나만 밖으로 열어 둔다. 이러면 어느 VM 이 어디에 접속했는지 로그가 한곳에 남고, apt·pip 패키지는 프록시 캐시에 있으면 두 번째부터 즉시 온다. 학교 도서관 논문 사이트가 교내에서만 열리는 것도 도서관 프록시가 "학교 IP" 로 대신 접속해 주기 때문이다.

면접에서는 거의 항상 "포워드 프록시와 리버스 프록시의 차이는?" 으로 나온다. 한 줄 답은 **누구를 대신하느냐** — 포워드는 클라이언트를 대신해 나가고(서버는 진짜 클라이언트를 모름), 리버스는 서버를 대신해 받는다(클라이언트는 진짜 서버를 모름).

## 헷갈리기 쉬운 것

- **리버스 프록시**는 방향이 반대. 포워드 프록시는 클라이언트 쪽에 서서 "나가는" 요청을 대신하고, 리버스 프록시(Caddy)는 서버 앞에 서서 "들어오는" 요청을 대신 받는다.
- **VPN** 은 OS 의 모든 트래픽을 암호화 터널에 넣는다. 프록시는 설정한 앱(브라우저·pip)의 요청만 중계하고 암호화가 필수는 아니다.
- **NAT** 도 "대신 나가는" 것처럼 보이지만 IP 와 포트만 바꿔 줄 뿐 내용을 모른다. 프록시는 HTTP 를 이해해서 캐시하고 도메인별로 막을 수 있다.
