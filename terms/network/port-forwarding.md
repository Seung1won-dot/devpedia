## 한 줄 정의

공유기 **바깥 포트로 온 접속을 안쪽 특정 장비의 포트로** 넘겨 주는 설정.

## 비유

아파트 **경비실의 택배 전달**. 바깥 사람은 "101동 경비실, 8000번" 까지만 알고 보내면 되고, 경비실이 "8000번은 1203호" 라는 표를 보고 집까지 올려 준다.

## 예시

```text
공유기 관리 화면 > 포트포워딩(가상 서버)
  외부 포트 2222 / TCP  →  내부 IP 192.168.10.20, 내부 포트 22
```

```bash
curl ifconfig.me                   # 내 공인 IP 확인 — 밖에서는 이 주소로 들어온다
ssh -p 2222 user@<집 공인 IP>      # 공유기 2222 → 안쪽 서버 22(SSH)
```

사설 IP 는 밖에서 보이지 않으므로 이 표가 없으면 들어올 길 자체가 없다. 몇 가지 현실: 공인 IP 가 통신사 사정으로 바뀌므로 DDNS 를 같이 쓰고, 열린 포트는 전 세계 봇이 하루 종일 두드리니 SSH 는 키 인증 + fail2ban 이 기본이다. 학교망이나 일부 통신사처럼 공유기 **앞에 또 NAT 가 있으면**(CGNAT) 내 공유기 설정만으론 안 되는데, 연구실이 포트를 아예 안 열고 Tailscale 로 들어오는 이유가 이것이다.

## 헷갈리기 쉬운 것

- **NAT** 는 안↔밖 주소 변환 전체를 가리키는 큰 기능, 포트 포워딩은 그중 밖→안 방향 규칙 한 줄(DNAT). 공유기 메뉴 이름이 "가상 서버" 인 제품도 있다.
- **포트 매핑(`docker -p 8080:80`)** 은 같은 원리를 공유기가 아니라 한 컴퓨터 안(호스트↔컨테이너)에서 하는 것. 밖에서 컨테이너까지 들어오려면 공유기 포트 포워딩 + 도커 포트 매핑 두 단계가 모두 맞아야 한다.
- **SSH 포트 포워딩(`ssh -L 8000:localhost:8000`)** 은 이름만 같고, 이미 열린 SSH 연결 안에 터널을 뚫는 것이라 공유기 설정이 필요 없다.
