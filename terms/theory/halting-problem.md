## 한 줄 정의

임의의 프로그램이 **멈출지 영원히 돌지** 항상 맞게 판정하는 알고리즘은 없다는 정리.

## 비유

**"이 문장이 거짓이라고 예언하는 예언가"**. 만능 예언가가 있다고 치면 "예언가가 멈춘다고 하면 무한히 돌고, 돈다고 하면 멈추는" 심술궂은 프로그램을 만들 수 있어 예언가가 반드시 틀린다.

## 예시

```python
# 귀류법 스케치: halts(f) 가 '항상 맞게' 판정한다고 가정하면
def trouble():
    if halts(trouble):   # 멈춘다고 판정하면
        while True:      # 영원히 돈다
            pass
    # 돈다고 판정하면 바로 멈춘다 → 어느 쪽이든 halts 가 틀림 → 모순
```

실무 의미: **모든 버그를 잡는 정적 분석기는 원리적으로 만들 수 없다**. 라이스 정리로 일반화하면 "이 함수가 None 을 반환할 수 있나", "이 코드에 무한 루프가 있나" 같은 의미적 성질은 모두 완벽 판정이 불가능하다. 그래서 린터·타입 검사기·SAST 는 트레이드오프를 고른다. 안전하게 의심되면 다 경고하거나(오탐↑, mypy 의 보수적 판정), 확실한 것만 잡거나(놓침↑). 테스트·타임아웃·코드 리뷰가 여전히 필요한 이유다.

## 헷갈리기 쉬운 것

- "정지 판정이 **어렵다**"가 아니라 "**불가능**하다"다. 컴퓨터가 빨라져도 해결되지 않는다. 반면 NP-완전은 "아마 빠르게는 못 푼다"는 효율 문제.
- **특정 프로그램**의 정지 여부는 판정할 수 있는 경우가 많다. 불가능한 것은 "모든 프로그램에 대해 항상 맞는" 판정기다.
