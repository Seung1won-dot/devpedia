## 한 줄 정의

그래프를 코드에 담는 두 방식으로, **V×V 표**에 적거나 **정점마다 이웃 목록**을 두는 것.

## 비유

**반 친구 관계도**를 그릴 때, 전원 이름을 가로세로로 적은 표에 친구면 O 를 치는 게 행렬이고, 각자 이름 옆에 친구 이름만 쭉 적는 게 리스트다.

## 예시

```python
V = 4
edges = [(0, 1), (0, 2), (1, 2), (2, 3)]

matrix = [[0] * V for _ in range(V)]        # 인접 행렬: V*V 칸
adj = [[] for _ in range(V)]                # 인접 리스트: 정점마다 이웃 목록
for u, v in edges:
    matrix[u][v] = matrix[v][u] = 1         # 무방향이면 양쪽 다 표시
    adj[u].append(v); adj[v].append(u)

matrix[0][2] == 1        # 간선 존재 확인: O(1)
2 in adj[0]              # 간선 존재 확인: O(차수)
adj[2]                   # 2 의 이웃 전부: [0, 1, 3] — 행렬은 한 줄 V 칸을 다 훑어야 한다
```

정점 10만 개짜리 그래프를 행렬로 잡으면 10^10 칸이라 메모리부터 터지지만(O(V²)), 리스트는 간선 수만큼만 쓴다(O(V+E)). 코딩테스트 그래프 문제는 거의 항상 인접 리스트로 시작하고, 정점이 수백 개 이하이면서 "두 점이 이어져 있나" 를 자주 묻거나 플로이드-워셜을 돌릴 때만 행렬을 쓴다. 면접에선 "두 표현의 메모리와 간선 조회 시간 차이는?", "희소 그래프엔 어느 쪽이 유리한가?" 로 나온다.

## 헷갈리기 쉬운 것

- **희소/밀집 그래프**: 간선이 V² 에 가까우면(밀집) 행렬이 낭비가 없고, 대부분의 실제 그래프(SNS, 도로망)는 희소해서 리스트가 맞다.
- **간선 리스트**: `[(0, 1), (0, 2), ...]` 처럼 간선만 나열한 것. 입력 형식이나 크루스칼처럼 간선을 정렬할 때 쓰고, 이웃 탐색엔 불편하다.
- **딕셔너리 표현**: 정점이 문자열이면 `dict[str, list]` 로 인접 리스트를 만든다. 본질은 같다.
