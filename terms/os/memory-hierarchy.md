## 한 줄 정의

빠르고 작은 저장장치부터 느리고 큰 것까지 **층층이 쌓아** 속도와 용량을 다 잡는 구조.

## 비유

**손(레지스터) → 책상(캐시) → 책장(RAM) → 창고(SSD) → 시내 도서관(HDD·네트워크)**. 가까울수록 빨리 꺼내지만 조금밖에 못 두고, 멀수록 많이 두지만 다녀오는 데 오래 걸린다.

## 예시

| 층 | 용량(대략) | 접근 시간(대략) | 1클럭 = 1초로 치면 |
|---|---|---|---|
| 레지스터 | 수백 바이트 | 0.3 ns | 1초 |
| L1 캐시 | 32~64 KB | 1 ns | 3초 |
| L2 캐시 | 1~2 MB | 4 ns | 13초 |
| L3 캐시 | 수십 MB | 10~40 ns | 30초~2분 |
| RAM | 수십~수백 GB | 100 ns | 5분 |
| NVMe SSD | 수 TB | 100 µs | 4일 |
| 네트워크(같은 데이터센터) | - | 0.5 ms | 3주 |
| HDD | 수십 TB | 10 ms | 1년 |

```bash
lscpu | grep -i cache          # L1d 32K / L2 1M / L3 32M
free -h | head -2              # RAM
nvidia-smi --query-gpu=memory.total --format=csv   # VRAM — GPU 쪽의 'RAM' 층
```

층마다 한 칸 내려갈 때마다 대략 10배씩 느려지고 그만큼 싸진다. 이 구조가 먹히는 건 지역성 덕분으로, 자주 쓰는 것만 위층에 올려 두면 평균 접근 시간은 위층에 가깝고 용량은 아래층에 가까워진다. GPU 서버에서 모델이 VRAM 에 안 들어가 RAM 으로 넘치면 수십 배 느려지고, 데이터셋이 RAM 에 안 들어가 SSD 를 매번 읽으면 또 수백 배 느려지는 것이 이 표 그대로다. 면접에서는 "메모리 계층이 왜 필요한가?", "캐시와 RAM 접근 시간은 대략 몇 배 차이인가?" 를 묻는다.

## 헷갈리기 쉬운 것

- **속도가 빠른 것과 용량이 큰 것은 같은 물건이 아니다**: SRAM(캐시)은 빠르지만 비싸고 크며, DRAM(RAM)은 그보다 싸고 느리며, 플래시(SSD)는 더 싸고 더 느리다. 그래서 "전부 다 캐시로" 는 못 한다.
- **휘발성 경계**: 레지스터~RAM 은 전원이 꺼지면 사라지고 SSD 부터는 남는다. "메모리" 와 "저장 공간" 을 나누는 선이 여기.
- **숫자는 자릿수만 기억**: 표의 값은 세대·제품마다 다르고, ns → µs → ms 로 자릿수가 바뀌는 감각이 핵심이다.
