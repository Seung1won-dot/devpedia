## 한 줄 정의

장치나 프로그램이 CPU 에 **하던 일을 멈추고 이것부터 봐 달라**고 보내는 신호.

## 비유

요리 중에 울리는 **초인종**. 문 앞을 계속 내다보는 대신(폴링) 벨이 울릴 때만 불을 줄이고 나가서 택배를 받은 뒤 하던 요리로 돌아온다.

## 예시

```bash
watch -n1 'grep -E "^ *(LOC|[0-9]+:.*(nvme|enp|nvidia))" /proc/interrupts'
#        CPU0    CPU1  ...
#  24: 812345       0  IR-PCI-MSI  nvme0q0        ← SSD 가 "읽기 끝났어" 알림
#  57:  93011       0  IR-PCI-MSI  enp5s0-TxRx-0  ← 네트워크 패킷 도착
# 131:   1023       0  IR-PCI-MSI  nvidia         ← GPU 커널 실행 완료
# LOC: 2049182 1987211  Local timer interrupts    ← 타이머 (스케줄러의 심장박동)
```

`/proc/interrupts` 의 숫자가 초마다 오르는 게 하드웨어 인터럽트다. SSD 에 읽기를 시켜 놓고 CPU 는 다른 프로세스를 돌리다가, 완료 인터럽트가 오면 현재 상태를 저장하고 **ISR(인터럽트 서비스 루틴)** 로 점프해 처리한 뒤 돌아온다. 타이머 인터럽트가 없으면 스케줄러가 돌던 프로세스를 뺏을 방법이 없어 선점형 스케줄링 자체가 불가능하다. 면접에서는 "인터럽트 처리 과정", "폴링과 인터럽트의 차이", "트랩과 인터럽트의 차이" 를 묻는다.

### 처리 순서

현재 명령 마무리 → PC·레지스터 저장(커널 스택 또는 PCB) → 인터럽트 벡터 테이블에서 번호에 맞는 ISR 주소 찾기 → 커널 모드로 ISR 실행 → 상태 복원 후 원래 자리로 복귀.

## 헷갈리기 쉬운 것

- **폴링 vs 인터럽트**: 폴링은 CPU 가 "끝났어?" 를 계속 물어보는 것이라 CPU 를 낭비하지만 지연이 일정하다. 인터럽트는 장치가 알려 줄 때까지 CPU 가 딴 일을 한다. 고속 네트워크 카드는 인터럽트가 너무 잦아 오히려 폴링으로 바꾸기도 한다(NAPI).
- **하드웨어 인터럽트 vs 트랩/예외**: 인터럽트는 바깥 장치가 비동기로 보내는 것, 트랩·예외는 CPU 가 명령을 실행하다 스스로 일으키는 것(0 으로 나누기, 페이지 폴트, 시스템 콜 명령). 시스템 콜은 "일부러 내는 트랩" 이다.
- **시그널(SIGTERM 등)** 은 커널이 프로세스에게 보내는 소프트웨어 차원의 알림. 인터럽트는 하드웨어가 커널에게, 시그널은 커널이 프로세스에게.
