## 한 줄 정의

대기 중인 프로세스 중 **누구에게 CPU 를 먼저, 얼마나 줄지** 정하는 규칙들.

## 비유

은행 창구에서 손님 순서 정하기. **온 순서대로(FCFS)**, **볼일 짧은 사람 먼저(SJF)**, **한 사람당 3분씩 돌아가며(RR)**, **VIP 먼저(우선순위)** 중 뭘 고르느냐에 따라 평균 대기 시간과 불만이 달라진다.

## 예시

```text
프로세스   P1=24  P2=3  P3=3   (모두 시각 0 에 도착, 숫자는 실행 시간)
FCFS  : |      P1(24)      |P2|P3|        평균 대기 = (0+24+27)/3 = 17
SJF   : |P2|P3|      P1(24)      |        평균 대기 = (0+3+6)/3   = 3
RR(4) : |P1|P2|P3|P1|P1|P1|P1|P1|        평균 대기 = (6+4+7)/3   = 5.7
```

같은 세 작업인데 순서만 바꿔도 평균 대기 시간이 17 → 3 으로 줄어든다(SJF 가 평균 대기 시간 최적). 대신 SJF 는 실행 시간을 미리 알 수 없고, 짧은 작업이 계속 들어오면 긴 작업은 영원히 못 도는 **기아(starvation)** 가 생긴다. 이걸 막는 게 기다린 시간만큼 우선순위를 올려 주는 **에이징(aging)** 이다. 리눅스 기본 스케줄러(CFS/EEVDF)는 이 중 하나가 아니라 "지금까지 CPU 를 가장 적게 받은 놈 먼저" 로 공평함을 맞춘다.

면접 단골 질문은 "선점형과 비선점형의 차이는?", "RR 의 타임 슬라이스가 너무 크면/작으면?" 이다. 너무 크면 FCFS 와 같아지고, 너무 작으면 컨텍스트 스위칭 비용이 실제 일보다 커진다.

## 헷갈리기 쉬운 것

- **선점(preemptive) vs 비선점**: 선점은 돌고 있는 프로세스를 도중에 뺏을 수 있음(RR, SRTF, 우선순위 선점형). 비선점은 스스로 끝내거나 I/O 로 나갈 때까지 기다림(FCFS, SJF). 대화형 OS 는 전부 선점형.
- **SJF vs SRTF**: SRTF(최단 잔여 시간 우선)는 SJF 의 선점형 버전. 더 짧은 게 도착하면 지금 것을 멈추고 갈아탄다.
- **호위 효과(convoy effect)**: FCFS 에서 긴 작업 하나 뒤에 짧은 작업들이 줄줄이 기다리는 현상. 위 예시의 FCFS 가 바로 그것.
