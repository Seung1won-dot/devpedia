## 한 줄 정의

**프로그램과 데이터를 같은 메모리에** 두고 CPU 가 순서대로 꺼내 실행하는 컴퓨터 구조.

## 비유

**레시피와 재료를 같은 냉장고에 넣어 두는 주방**. 요리사는 냉장고에서 레시피 한 줄을 꺼내 읽고, 다시 냉장고에서 재료를 꺼내 처리하는데, 냉장고 문이 하나라 한 번에 하나씩만 꺼낼 수 있다.

## 예시

```python
mem = [("LOAD", 5), ("ADD", 6), ("STORE", 7), ("HALT", 0), 0, 3, 4, 0]
#      └── 명령어 (주소 0~3) ──────────────────┘  └ 데이터 (주소 4~7) ┘
pc, acc = 0, 0
while True:
    op, addr = mem[pc]; pc += 1          # fetch: PC 가 가리키는 칸을 읽는다
    if   op == "LOAD":  acc = mem[addr]  # decode + execute
    elif op == "ADD":   acc += mem[addr]
    elif op == "STORE": mem[addr] = acc
    elif op == "HALT":  break
print(mem[7])                            # 7  (3 + 4)
```

명령어도 데이터도 같은 리스트 `mem` 에 들어 있고, CPU 는 그저 PC 가 가리키는 칸을 읽어 실행할 뿐이다. 그래서 프로그램을 "데이터처럼" 디스크에서 RAM 에 올려 실행할 수 있고, 반대로 버퍼 오버플로로 데이터 영역에 넣은 값이 코드로 실행되는 공격도 가능하다. CPU 는 계속 빨라졌는데 메모리에서 명령어와 데이터를 꺼내오는 통로 하나가 병목이 되는 게 **폰 노이만 병목**이고, 캐시·파이프라이닝·GPU 의 대역폭 설계가 전부 이걸 완화하려는 것이다. 면접에서는 "폰 노이만 구조의 특징과 병목", "하버드 구조와의 차이" 로 나온다.

## 헷갈리기 쉬운 것

- **하버드 구조**는 명령어 메모리와 데이터 메모리를 물리적으로 나눠 동시에 읽는 구조(MCU, DSP). 현대 CPU 는 겉은 폰 노이만이지만 L1 캐시를 명령어(L1i)·데이터(L1d)로 쪼개 안쪽만 하버드처럼 쓴다(수정된 하버드).
- **폰 노이만 병목 vs 메모리 벽(memory wall)**: 병목은 "통로가 하나" 라는 구조 문제, 메모리 벽은 "CPU 속도만 빨라져 격차가 벌어진" 현상. 둘이 합쳐져 메모리 계층이 필요해졌다.
- **명령어와 데이터의 구분은 해석 차이일 뿐**: 같은 비트열을 PC 가 가리키면 명령어, 피연산자로 읽으면 데이터. 그래서 OS 는 코드 영역을 읽기 전용·실행 가능, 데이터 영역을 실행 불가(NX 비트)로 표시해 둘을 억지로 갈라 둔다.
