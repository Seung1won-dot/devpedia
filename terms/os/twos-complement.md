## 한 줄 정의

음수를 **비트를 뒤집고 1 을 더한 값**으로 나타내 덧셈 회로 하나로 뺄셈까지 하는 방식.

## 비유

**자동차 주행계**를 0 에서 뒤로 1 돌리면 999999 가 된다. 999999 를 "-1" 로 약속하면 뺄셈도 그냥 앞으로 돌리는 것(덧셈)으로 처리할 수 있다.

## 예시

```python
def to_int8(x):                      # 8비트 2의 보수로 해석
    x &= 0xFF
    return x - 256 if x & 0x80 else x

print(f"{-5 & 0xFF:08b}")            # 11111011  (00000101 뒤집기 → 11111010, +1)
print(to_int8(0b11111011))           # -5
print(to_int8(0b01111111 + 1))       # -128 ← 127 + 1 이 넘쳐서 음수로 (오버플로)

import numpy as np
np.int8(127) + np.int8(1)            # -128 (RuntimeWarning: overflow)
```

int8 은 `-128 ~ 127` 이다. 맨 앞 비트가 부호를 겸해서 양수는 0~127 (2^7 - 1), 음수는 -1~-128 로 음수가 하나 더 많다. `127 + 1` 이 `-128` 이 되는 것이 정수 오버플로이고, 파이썬 `int` 는 크기가 자동으로 늘어나 안 나지만 C·Java·NumPy·PyTorch 텐서는 그대로 난다. 딥러닝 int8 양자화가 가중치를 이 256개 값 안에 욱여넣는 작업이다. 면접에서는 "왜 1의 보수가 아니라 2의 보수를 쓰나?"(0 이 하나뿐이고 덧셈 회로를 그대로 씀), "int8 의 범위와 이유" 로 나온다.

## 헷갈리기 쉬운 것

- **1의 보수**는 비트만 뒤집은 것. +0(00000000)과 -0(11111111)이 둘 다 생기고 덧셈 후 자리올림을 다시 더해야 해서 안 쓴다.
- **부호 있는 정수 vs 부호 없는 정수**: 같은 비트 `11111111` 이 int8 에선 -1, uint8 에선 255. 이미지 픽셀은 uint8(0~255), CT 의 HU 값은 int16. C 에서 이걸 헷갈리면 `if (len < 0)` 이 절대 참이 안 되는 버그가 난다.
- **부동소수점**은 전혀 다른 방식이라 `-0.0` 이 실제로 존재한다.
