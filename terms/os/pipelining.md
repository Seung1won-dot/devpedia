## 한 줄 정의

명령어 처리를 여러 단계로 쪼개 **서로 다른 명령어를 동시에 겹쳐** 진행하는 기법.

## 비유

**세탁소의 세탁기·건조기·다리미**. 첫 빨래가 건조기로 넘어가면 세탁기는 놀지 않고 다음 빨래를 돌려서, 한 벌 끝나는 시간은 같아도 시간당 나오는 옷 수는 3배가 된다.

## 예시

```text
5단계: IF(가져오기) ID(해독) EX(실행) MEM(메모리) WB(레지스터 쓰기)

사이클     1    2    3    4    5    6    7
명령어 1   IF   ID   EX   MEM  WB
명령어 2        IF   ID   EX   MEM  WB
명령어 3             IF   ID   EX   MEM  WB      ← 5사이클 뒤부터 매 사이클 1개씩 완료
```

```c
// 같은 데이터인데 정렬만 하면 2~5배 빨라지는 유명한 예 (분기 예측)
for (int i = 0; i < n; i++)
    if (data[i] >= 128) sum += data[i];   // 무작위면 예측이 절반 틀림
```

`if (data[i] >= 128)` 을 만나면 CPU 는 비교 결과가 나오기 전에 한쪽을 **예측**해 다음 명령어를 미리 파이프라인에 넣는다. 정렬된 데이터는 앞부분은 전부 거짓, 뒷부분은 전부 참이라 예측이 거의 다 맞지만, 무작위 데이터는 절반이 틀려 그때마다 파이프라인을 비우고 다시 채운다(수십 사이클 손해). 면접에서는 "파이프라인 해저드 3종과 해결법", "분기 예측이 왜 필요한가" 로 나온다.

### 해저드 3종

| 종류 | 원인 | 대응 |
|---|---|---|
| 데이터 해저드 | 앞 명령 결과를 뒤 명령이 바로 씀 | 포워딩, 스톨(잠깐 멈춤), 명령 순서 재배치 |
| 제어 해저드 | 분기 결과를 알기 전에 다음 명령을 가져와야 함 | 분기 예측, 지연 분기 |
| 구조 해저드 | 두 단계가 같은 하드웨어(메모리 포트 등)를 동시에 원함 | 자원 분리 (L1i/L1d 캐시 분리) |

## 헷갈리기 쉬운 것

- **파이프라이닝 vs 병렬 처리**: 파이프라이닝은 코어 하나 안에서 단계를 겹치는 것(처리량은 오르지만 명령 하나의 지연은 그대로). 멀티코어는 요리사를 늘리는 것. 둘은 같이 쓰인다.
- **클럭이 높다고 빠른 게 아니다**: 단계를 잘게 쪼개면(20단계 이상) 클럭은 올라가지만 예측이 틀렸을 때 버리는 양도 커진다. Spectre 취약점도 이 "미리 실행한 흔적" 을 캐시에서 읽어 낸 것이다.
