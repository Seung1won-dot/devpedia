## 한 줄 정의

UI 문구·날짜·숫자를 **코드 수정 없이 여러 언어로 바꿔 보여 줄 수 있게** 만드는 설계.

## 비유

영화의 **자막 파일**. 영상(코드)은 그대로 두고 자막(번역 파일)만 갈아 끼우면 한국어든 영어든 상영할 수 있다.

## 예시

```ts
// src/i18n.ts — 문구를 코드에서 빼서 언어별 사전으로 (로드맵 사이트에 영문 모드를 붙인다면)
import i18n from 'i18next'
import { initReactI18next } from 'react-i18next'

i18n.use(initReactI18next).init({
  resources: {
    ko: { translation: { title: '학년별 로드맵', terms: '{{count}}개 용어' } },
    en: { translation: { title: 'Roadmap by Year', terms_one: '{{count}} term', terms_other: '{{count}} terms' } },
  },
  lng: localStorage.getItem('lang') ?? 'ko',
  fallbackLng: 'ko',
})
```

```tsx
// 컴포넌트는 키만 부른다
const { t, i18n } = useTranslation()
<h1>{t('title')}</h1>
<p>{t('terms', { count: 377 })}</p>                          {/* ko: 377개 용어 / en: 377 terms */}
<button onClick={() => i18n.changeLanguage('en')}>EN</button>
```

핵심은 **문구를 코드 밖으로** 빼는 것. 번역문은 `ko.json`·`en.json` 같은 파일로 두고 컴포넌트는 키(`title`)만 부른다. 글자만 바꾸면 끝이 아니다 — 영어 복수형, 날짜·숫자 형식(`Intl.DateTimeFormat`), 긴 독일어 단어에 버튼이 터지는 것, `<html lang>` 과 아랍어 오른쪽→왼쪽 쓰기까지 챙겨야 진짜 다국어다. 하드코딩된 한국어가 수백 군데 박힌 뒤에 빼내는 건 매우 괴로우므로, 영문 모드가 조금이라도 예상되면 처음부터 `t()` 로 감싸 두는 편이 싸다.

## 헷갈리기 쉬운 것

- **i18n vs l10n**: i18n(internationalization, i 와 n 사이 18글자)은 **바꿀 수 있게 만드는 설계**, l10n(localization)은 **특정 언어·지역에 맞게 실제로 채우는 작업**(번역, 통화, 날짜). 설계가 돼 있어야 l10n 이 싸진다.
- **언어 vs 로케일**: `ko` 는 언어, `ko-KR` 은 언어+지역. 날짜 형식(미국 MM/DD vs 영국 DD/MM)은 언어가 같은 영어라도 지역에 따라 다르다.
- **a11y(접근성)** 는 장애·보조기기 대응, i18n 은 언어·지역 대응. `lang` 속성처럼 겹치는 지점이 있다(스크린리더가 발음 언어를 고를 때 쓴다).
