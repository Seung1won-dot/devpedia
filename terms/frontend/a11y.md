## 한 줄 정의

시각·운동 장애가 있거나 **키보드·화면 낭독기만 쓰는 사람도** 웹을 쓸 수 있게 만드는 것.

## 비유

건물의 **경사로와 점자 안내판**. 계단만 있으면 못 들어오는 사람이 생기는데, 경사로를 놓으면 유모차나 캐리어 끄는 사람에게도 편해진다.

## 예시

```tsx
// Devpedia 별표 버튼. 아이콘만 있으면 낭독기는 "버튼" 이라고만 읽는다
<button onClick={toggle}>★</button>

// aria-label 을 주면 "복습 목록에 추가, 버튼" 으로 읽고, aria-pressed 로 켜짐 상태까지 알린다
<button onClick={toggle} aria-label="복습 목록에 추가" aria-pressed={starred}>★</button>
```

가장 흔한 세 가지: 이미지에 `alt`, 글자와 배경의 명도 대비 4.5:1 이상, 마우스 없이 **Tab 키만으로** 모든 버튼에 갈 수 있을 것. Chrome 개발자 도구의 Lighthouse 탭에서 Accessibility 점수로 대략 확인한다.

## 헷갈리기 쉬운 것

- **반응형 디자인** 은 화면 크기에 맞추는 것, 접근성은 사람의 조건에 맞추는 것. 둘 다 "누구나 쓸 수 있게" 지만 대상이 다르다.
- **i18n(다국어)** 은 언어에 맞추는 것. 숫자 약어 습관은 같다(a11y = a + 11글자 + y, i18n = i + 18글자 + n).
