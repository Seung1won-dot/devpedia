## 한 줄 정의

층마다 **여러 전문가 중 몇 개만 골라 계산**해 파라미터는 많고 연산은 적은 모델 구조.

## 비유

종합병원 접수처. 환자(토큰)마다 안내 데스크(라우터)가 "이분은 내과와 정형외과만" 하고 보내 주니, 의사(전문가)가 수백 명이어도 환자 한 명이 실제로 만나는 건 둘뿐이라 진료가 빠르다.

## 예시

```bash
ollama pull qwen3:30b-a3b      # 전체 파라미터 30B, 토큰당 활성 약 3B  [확인 필요]
ollama list
# qwen3:30b-a3b    약 18 GB   ← 4bit 인데도 전문가 전부가 VRAM 에 올라가야 한다  [확인 필요]
```

"30B-A3B" 는 가중치 30B 를 전부 들고 있되 토큰마다 3B 만 계산한다는 뜻이라, 속도는 3B 급으로 빠르고 아는 것은 그보다 많다. 트레이드오프의 핵심: 연산(속도)은 아끼지만 VRAM 은 못 아낀다 — 라우터가 어느 전문가를 고를지 모르니 전원이 메모리에 있어야 한다. 연구실 24GB 카드에서 4bit 30B-A3B 는 올라가고 빠르지만, 같은 VRAM 에 밀집(dense) 32B 4bit 를 올리면 더 똑똑한 대신 몇 배 느리다 [확인 필요]. 즉 "응답 속도가 중요하고 VRAM 은 넉넉" 하면 MoE, "VRAM 이 빠듯하고 품질 우선" 이면 밀집 모델이다. 학습은 전문가별 부하를 고르게 맞추는 보조 손실이 필요하고 분산 학습에서 전문가를 GPU 별로 나눠 두는 식이라, 연구실에서 직접 학습할 일은 거의 없다.

## 헷갈리기 쉬운 것

- **파라미터 수(7B/70B)**: MoE 는 "총 파라미터" 와 "활성 파라미터" 두 숫자를 가진다. VRAM 은 총 파라미터, 속도는 활성 파라미터 기준.
- **앙상블**은 여러 모델을 전부 돌려 결과를 합치는 것. MoE 는 한 모델 안에서 일부만 골라 돌린다.
- **LLM 라우터**(질문에 따라 작은 모델/큰 모델 중 하나를 고르는 서비스 설계)와 헷갈리기 쉽지만, MoE 의 라우팅은 모델 내부에서 층마다·토큰마다 일어난다.
