## 한 줄 정의

작은 모델이 **토큰 여러 개를 먼저 추측**하고 큰 모델이 한 번에 검증해 생성을 빠르게 하는 기법.

## 비유

타자 빠른 후배가 문장을 먼저 쳐 두면 교수님은 읽으면서 틀린 곳부터만 고치는 것. 교수님이 한 글자씩 직접 치는 것보다 빠른데, 최종 글은 교수님이 쓴 것과 똑같다.

## 예시

```bash
# vLLM: Qwen2.5-7B 를 같은 계열 0.5B 드래프트 모델로 가속  [확인 필요: 버전마다 옵션 이름이 다름]
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --speculative-config '{"model": "Qwen/Qwen2.5-0.5B-Instruct", "num_speculative_tokens": 5}'
```

LLM 생성은 토큰 하나 만들 때마다 가중치 전체를 VRAM 에서 한 번 읽어야 해서, 큰 모델은 연산보다 메모리 읽기가 병목이다. 드래프트가 5개를 제안하면 큰 모델은 그 5개를 순전파 한 번으로 검증해 맞은 데까지 채택하고 틀린 지점부터 다시 시작하므로, 읽기 한 번에 토큰 여러 개가 나온다. 수학적으로 결과 분포는 큰 모델 혼자 만든 것과 같다. 트레이드오프: 드래프트 모델만큼 VRAM 과 연산이 더 들고, 드래프트가 자주 틀리는 텍스트(창의적인 글)에서는 오히려 느려질 수 있으며, 동시 요청이 많아 GPU 가 이미 연산으로 바쁜 서버에서는 이득이 줄어든다. 연구실 24GB 카드에 7B 4bit + 0.5B 드래프트는 들어가고, 혼자 쓰는 긴 코드·요약 생성에서 체감이 크다. 드래프트는 토크나이저가 같은 모델 계열이어야 하며, Ollama 는 아직 지원하지 않는다 [확인 필요].

## 헷갈리기 쉬운 것

- **양자화**는 모델 자체를 가볍게 해서 빨라지는 대신 답이 미묘하게 달라질 수 있다. 스페큘레이티브 디코딩은 답은 그대로고 속도만 빨라진다.
- **KV 캐시**는 앞 토큰 재계산을 없애는 것, 스페큘레이티브는 한 번에 여러 토큰을 검증하는 것. 둘은 같이 쓴다.
- **디스틸레이션**으로 만든 작은 모델이 드래프트로 쓰기 좋지만, 디스틸은 작은 모델이 최종 답을 내고 스펙 디코딩은 큰 모델이 최종 답을 낸다.
- **처리량 vs 지연**: 스펙 디코딩은 한 사용자의 응답 지연을 줄인다. 여러 요청의 처리량을 올리는 건 배치와 vLLM 의 몫.
