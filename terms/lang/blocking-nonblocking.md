## 한 줄 정의

함수를 불렀을 때 **제어권이 바로 돌아오는지**(논블로킹) 아닌지(블로킹)의 구분.

## 비유

은행 창구에 서류를 냈을 때 **창구 앞에 붙잡혀 있는지**(블로킹), "접수됐으니 가 보세요" 하고 **바로 풀려나는지**(논블로킹)의 문제다. 풀려난 뒤 결과를 내가 계속 확인하러 오면 동기, 은행이 문자로 알려 주면 비동기다.

## 예시

동기/비동기와는 **축이 다르다**. 하나는 "제어권이 바로 돌아오나", 하나는 "완료를 누가 확인하나" 라서 네 조합이 다 있다.

| | 동기 (완료를 내가 확인) | 비동기 (완료를 통보받음) |
|---|---|---|
| **블로킹** (제어권 안 돌아옴) | `input()`, 기본 소켓 `recv()` — 제일 흔한 형태 | 드묾 — 비동기로 시켜 놓고 결과까지 멈춰 기다림 |
| **논블로킹** (제어권 바로 돌아옴) | `O_NONBLOCK` 소켓 + 폴링 루프 — 바로 돌아오지만 내가 계속 물어봄 | Node 의 `fs.promises`, `fetch` — 바로 돌아오고 끝나면 콜백이 불림 |

```python
import socket
s = socket.create_connection(("gpu-server", 11434))
s.setblocking(False)              # 논블로킹으로 전환
try:
    data = s.recv(1024)           # 데이터 없으면 멈추지 않고 즉시 예외
except BlockingIOError:
    data = None                   # 제어권이 돌아왔으니 다른 일 하고 다시 시도
```

블로킹 소켓이면 `recv()` 에서 데이터가 올 때까지 이 스레드는 아무것도 못 한다. 논블로킹은 즉시 돌아오는 대신 결과 확인을 내가 반복해야 하니 **동기 + 논블로킹**이다. Node 나 Python `asyncio` 는 이 논블로킹 I/O 위에 이벤트 루프를 얹어 "끝나면 콜백을 불러 주는" **비동기 + 논블로킹**을 만든다.

면접에선 "동기/비동기와 블로킹/논블로킹의 차이는?" 이 단골이다 — 앞은 **완료 확인의 주체**, 뒤는 **제어권 반환 여부**라고 축을 나눠 답한다.

## 헷갈리기 쉬운 것

- **동기/비동기**: 실무에선 "블로킹 = 동기, 논블로킹 = 비동기" 로 뭉뚱그려 쓰지만, 위 표처럼 동기 + 논블로킹(폴링)이 엄연히 있다.
- **멀티스레드**: 블로킹 호출을 스레드 여러 개로 나눠 돌리면 전체는 안 멈추지만 각 호출은 여전히 블로킹이다. 논블로킹은 스레드 하나로도 안 멈추는 것.
