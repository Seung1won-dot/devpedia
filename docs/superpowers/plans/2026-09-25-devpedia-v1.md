# Devpedia v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 13개 카테고리 IT 용어를 "한 줄 정의 + 비유 + 예시 + 관련 용어" 카드로 탐색·검색하는 정적 PWA 사전(Devpedia)을, Markdown 콘텐츠 → 빌드 검증 → GitHub Pages 배포 파이프라인과 함께 v1 완성 상태로 만든다.

**Architecture:** `terms/<category>/<id>.md`(frontmatter + 4 섹션)를 빌드 시 `scripts/`가 zod 로 검증하고 `public/terms.json`(HTML 렌더 완료 + 통계 + 역링크)으로 내보낸다. 클라이언트(Vite + React + TS SPA)는 그 JSON 하나를 fetch 해 MiniSearch 메모리 인덱스를 만들고, 해시 라우팅(`#ssh`, `#c/network`)으로 카테고리 탭·검색·카드 상세·관련 링크·별표·테마를 전부 클라이언트에서 처리한다. 서버 없음. vite-plugin-pwa 가 앱 셸과 `terms.json`을 프리캐시해 오프라인 열람을 보장한다.

**Tech Stack:** Node 22 · Vite · React 18 · TypeScript 5 · MiniSearch · gray-matter · marked · zod · yaml · tsx · vitest(+jsdom, @testing-library/react) · vite-plugin-pwa(Workbox) · @resvg/resvg-js(아이콘 생성) · GitHub Actions + Pages

**Spec:** `docs/superpowers/specs/2026-09-25-devpedia-design.md` (원본: `D:\EC LAB\shared\it-glossary-project-plan.md`)

## Global Constraints

- 스택: **Vite + React + TypeScript (SPA)**. 스타일은 **CSS 변수 + 다크 테마**, 의존성 0 (Tailwind 금지). (스펙 11장)
- 콘텐츠: **Markdown + YAML frontmatter**, 용어 하나 = 파일 하나 `terms/<category>/<id>.md`. 런타임 파싱 금지 — 빌드 때 JSON 으로. (스펙 6·11장)
- 검색: **MiniSearch** 클라이언트 인덱스, 한글·영문·약어, 입력 후 **100ms 이내** 결과 (K4).
- 필드 규칙(스펙 6장): `id` 영문 소문자·숫자·하이픈 / `aliases` 필수 / `category` 13개 코드 중 하나 / `tags` 는 `taxonomy/tags.yml` 에 정의된 것만 / `level` 1~3 / `related` 존재하지 않는 id 면 빌드 실패 / `## 한 줄 정의` 60자 이내·문장 하나 / `## 비유` 2문장 이내 / `## 예시` 필수 / `## 헷갈리기 쉬운 것` 선택.
- 카테고리 코드(고정 13개, 이 순서): `os`(🧠 컴퓨터 구조 & 운영체제) `network`(🌐 네트워크) `algo`(🧩 자료구조 & 알고리즘) `lang`(💬 프로그래밍 언어 & 패러다임) `frontend`(🖥️ 프론트엔드) `backend`(⚙️ 백엔드 & API) `database`(🗄️ 데이터베이스) `infra`(🖧 서버 & 인프라 & 클라우드) `devops`(🔧 DevOps & 개발 도구) `security`(🔒 보안) `ai`(🤖 AI / ML / LLM) `medical`(🏥 의료 IT) `swe`(📐 소프트웨어 공학 & 협업).
- 상태: `status: draft | review | published`. draft 는 본문·related 가 비어도 커밋 가능(경고만). review/published 는 전체 규칙 강제. **LLM 이 쓴 초안은 `review` 로만 넣는다** (스펙 9-1 "LLM 초안을 그대로 발행하지 않는 것이 규칙").
- 딥링크(F-05): `#<id>` 로 카드 직접 열기. 예약 해시: `#c/<code>`(카테고리), `#starred`, `#stats`. 따라서 `id` 는 `c`, `starred`, `stats`, `all` 및 카테고리 코드와 같을 수 없다(validate 가 막는다).
- 배포: GitHub Pages(Actions). `vite.config.ts` 의 `base` 는 env `BASE_PATH`(기본 `/`), CI 는 `/<repo>/` 로 넣는다.
- 성능: Lighthouse 90+, LCP < 1.5s (K5). 첫 로드 = index.html + app.js + terms.json + sw.js + manifest.
- 커밋 메시지: 코드 `feat|fix|chore|docs|test(scope): ...`, 용어는 `term(<category>): add <id>`. 모든 커밋 끝에 `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- 언어: UI 문구·문서 한국어. 코드 식별자 영어.

## Review Focus

1. **`##` 가 코드 펜스 안에 있는 예시** (예: bash 주석 `## 설치`) — 섹션 분리기가 이를 새 섹션으로 오인하면 예시가 잘린다. 펜스 안은 무시해야 한다. → Task 2 테스트 `splitSections ignores headings inside code fences`.
2. **frontmatter 날짜가 YAML Date 로 파싱되는 경우** (`created: 2026-09-25` 는 js-yaml 이 Date 객체로 만든다) — 문자열 스키마가 이를 거부하면 모든 카드가 빌드 실패. → Task 3 테스트 `accepts Date-typed created and normalizes to YYYY-MM-DD`.
3. **한글 초성·부분 문자열 검색** ("ㄹㅂㅅ", "록시") — 토큰 접두 매칭만으로는 못 잡는다. 초성 필드 + 부분 문자열 폴백이 있어야 한다. → Task 6 테스트 `finds by chosung query`, `finds by mid-word substring fallback`.
4. **해시에 인코딩된 문자·미지의 패턴** (`#c/`, `#%EC%9A%A9%EC%96%B4`, `#nonexistent`) — 라우터가 throw 하거나 빈 화면이면 공유 링크가 깨진다. 없는 id 는 "용어를 찾을 수 없음" 상태를 보여야 한다. → Task 6 테스트 `parseHash falls back to home on garbage`, Task 8 테스트 `unknown term id renders not-found state`.
5. **localStorage 가 막힌 환경**(사파리 프라이빗, 스토리지 차단) — 별표·테마 읽기/쓰기가 throw 하면 앱 전체가 죽는다. try/catch 로 기본값으로 돌아가야 한다. → Task 6 테스트 `loadStars returns empty set when storage throws`, `loadTheme returns system when storage throws`.

```ts
import { readFileSync } from 'node:fs'
import { join } from 'node:path'
import { parse } from 'yaml'
import type { Category } from '../../src/types'
export interface Taxonomy { categories: Category[]; tags: string[] }
export function loadTaxonomy(dir: string): Taxonomy {
  const cats = parse(readFileSync(join(dir, 'categories.yml'), 'utf8')) as { categories: Omit<Category, 'order'>[] }
  const tags = parse(readFileSync(join(dir, 'tags.yml'), 'utf8')) as { tags: string[] }
  const seen = new Set<string>()
  for (const t of tags.tags) { if (seen.has(t)) throw new Error(`tags.yml 중복 태그: ${t}`); seen.add(t) }
  return { categories: cats.categories.map((c, i) => ({ ...c, order: i })), tags: tags.tags }
}
```

import { describe, it, expect } from 'vitest'
import { parseTermMarkdown, splitSections } from './parse'
const SAMPLE = `---
id: ssh
term: SSH
aliases: [Secure Shell, 시큐어 셸]
category: infra
level: 1
related: [port, firewall]
created: 2026-09-25
---

## 한 줄 정의

다른 컴퓨터에 **암호화된 통신으로 원격 접속**하는 프로토콜이자 명령어.

## 비유

열쇠 달린 뒷문.

## 예시

\`\`\`bash
## 설치 (이 줄은 섹션이 아니다)
ssh user@10.0.0.5
\`\`\`
`
describe('parseTermMarkdown', () => {
  it('returns frontmatter and named sections', () => {
    const r = parseTermMarkdown(SAMPLE, 'terms/infra/ssh.md')
    expect(r.file).toBe('terms/infra/ssh.md')
    expect(r.frontmatter.id).toBe('ssh')
    expect(r.frontmatter.aliases).toEqual(['Secure Shell', '시큐어 셸'])
    expect(r.sections['한 줄 정의']).toBe('다른 컴퓨터에 **암호화된 통신으로 원격 접속**하는 프로토콜이자 명령어.')
    expect(r.sections['비유']).toBe('열쇠 달린 뒷문.')
  })
  it('splitSections ignores headings inside code fences', () => {
    const r = parseTermMarkdown(SAMPLE)
    expect(Object.keys(r.sections)).toEqual(['한 줄 정의', '비유', '예시'])
    expect(r.sections['예시']).toContain('## 설치')
    expect(r.sections['예시']).toContain('ssh user@10.0.0.5')
  })
  it('returns empty sections for a body without headings', () => {

```ts
import matter from 'gray-matter'
export interface RawTerm { file: string; frontmatter: Record<string, unknown>; sections: Record<string, string>; body: string }
export function splitSections(md: string): Record<string, string> {
  const out: Record<string, string> = {}
  let current: string | null = null
  let buf: string[] = []
  let inFence = false
  for (const line of md.split(/\r?\n/)) {
    if (/^\s*(```|~~~)/.test(line)) { inFence = !inFence; if (current !== null) buf.push(line); continue }
    const m = inFence ? null : /^##\s+(.+?)\s*$/.exec(line)
    if (m) { if (current !== null) out[current] = buf.join('\n').trim(); current = m[1]; buf = []; continue }
    if (current !== null) buf.push(line)
  }
  if (current !== null) out[current] = buf.join('\n').trim()
  return out
}
export function parseTermMarkdown(source: string, file = '<memory>'): RawTerm {
  const { data, content } = matter(source)
  return { file, frontmatter: data as Record<string, unknown>, sections: splitSections(content), body: content }
}
