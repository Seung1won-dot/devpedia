## 1\. 문제 정의

### 1-1. 관찰

컴공 3학년쯤 되면 수업·연구실·인터넷에서 마주치는 용어가 폭발적으로 늘어난다. 수업에선 프로세스·스레드·TCP·정규화를 배우고, 연구실에선 SSH·Proxmox·Docker·크론잡을 쓰고, 뉴스에선 LLM·RAG·MCP·에이전트가 나오고, 프로젝트 하다 보면 REST·CORS·JWT·ORM이 튀어나온다. 각각은 검색하면 나오지만 **"이게 어느 분야 얘기고, 내가 아는 저 용어와 어떤 관계인지"** 가 머릿속에서 정리되지 않는다.

### 1-2. 기존 방식의 한계

- **검색**: 용어 하나씩은 나오지만 맥락(카테고리·관계)이 없다. 매번 처음부터 읽는다.  
- **위키백과**: 너무 길고 학술적. "한 줄로 뭔지" 를 알고 싶은데 역사부터 시작한다.  
- **영어 용어집(MDN, Cloudflare, AWS)**: 잘 되어 있지만 자기 분야만 다루고, 영어다.  
- **노션에 직접 정리**: 시작은 하지만 구조가 없어 금방 방치된다. 검색·관계 표현이 약하다.  
- **ChatGPT에 물어보기**: 그때는 이해되지만 남지 않는다. 같은 걸 세 번 물어본다.

### 1-3. 문제 문장

> 컴공 학부생이 마주치는 용어 전체를 **카테고리 지도 위에 놓고**, 각 용어를 **10초 안에 이해할 수 있는 카드**로, **내가 직접 쓰고 고치며 쌓아가는** 도구가 없다.

핵심은 마지막 구절이다. 남이 쓴 사전을 읽는 것보다 **내가 쓰면서 정리되는 것**이 목적이다. 그래서 콘텐츠 작성 워크플로(9장)가 기능(7장)만큼 중요하다.

### 차별점

1. **카테고리가 곧 지도** — 13개 카테고리 탭으로 "이 용어가 어느 층에 사는지" 가 먼저 보인다.  
2. **카드 한 장 \= 10초** — 한 줄 정의, 비유, 실제 예시(명령·코드·문장), 관련 용어 3\~5개. 그 이상은 외부 링크.  
3. **관련 용어 그래프** — 카드에서 관련 용어를 누르면 그 카드로. "SSH → 포트 → 방화벽 → VPN" 처럼 꼬리를 물고 학습.  
4. **Git 으로 관리되는 콘텐츠** — 용어 하나가 파일 하나. 커밋 히스토리가 곧 학습 기록. 나중에 남이 PR 로 기여 가능.  
5. **실제 내 환경의 예시** — "Proxmox 에서 VM 만들 때…", "Hermes 크론잡에서…" 처럼 내 연구실 맥락의 예시가 들어간다. 남의 사전엔 없는 부분.

## 4\. 사용자 시나리오

**S1. 수업 중** — 운영체제 시간에 "컨텍스트 스위칭" 이 나왔다. 폰으로 사전 열어 검색, 카드 10초 읽고 "프로세스", "스케줄러" 관련 카드로 넘어가 개념을 연결한다.

**S2. 연구실에서** — 선배가 "리버스 프록시 뒤에 두면 돼" 라고 했다. 검색해 카드를 읽고, 예시에 적어둔 Caddy 설정 두 줄을 그대로 써본다.

**S3. 새 용어 등록** — 논문에서 "LoRA" 를 봤다. `terms/ai/lora.md` 파일을 만들어 4필드 작성, 커밋. 다음 날 배포된 사이트에 카드가 생겼다. 커밋 로그에 학습 기록이 남는다.

**S4. 카테고리 훑기** — 시험 전에 "네트워크" 탭을 열어 카드 25장을 위에서 아래로 넘기며 빠르게 복습한다. 모르는 카드는 별표.

**S5. 남에게 설명** — 후배가 "도커가 뭐예요?" 물어서 카드 링크를 보내준다. 비유 한 줄로 이해시킨다.

**S6. 관계 탐색 (v2)** — 그래프 뷰에서 "인증" 주변을 보면 세션·쿠키·JWT·OAuth·SSO 가 어떻게 이어지는지 한눈에 들어온다.

## 5\. 카테고리 체계 (택소노미)

컴공 3학년까지의 커리큘럼과 연구실 맥락을 합쳐 **13개 대분류**. 각 대분류 아래 소분류(태그)를 두어 나중에 세분화.

| \# | 카테고리 | 아이콘 | 다루는 것 | 소분류 예 |
| :---- | :---- | :---: | :---- | :---- |
| 1 | **컴퓨터 구조 & 운영체제** | 🧠 | CPU·메모리·프로세스·파일시스템 | 하드웨어, 프로세스/스레드, 메모리, 파일시스템, 리눅스 |
| 2 | **네트워크** | 🌐 | 인터넷이 동작하는 원리 | TCP/IP, HTTP, DNS, 보안 통신, 무선 |
| 3 | **자료구조 & 알고리즘** | 🧩 | 문제를 푸는 도구와 비용 | 선형 구조, 트리/그래프, 정렬/탐색, 복잡도, DP |
| 4 | **프로그래밍 언어 & 패러다임** | 💬 | 언어 공통 개념 | 타입, OOP, 함수형, 메모리 관리, 비동기, 컴파일/인터프리터 |
| 5 | **프론트엔드** | 🖥️ | 브라우저에서 보이는 것 | HTML/CSS, JS 런타임, 프레임워크, 렌더링, PWA |
| 6 | **백엔드 & API** | ⚙️ | 요청을 받아 처리하는 것 | REST/GraphQL, 인증/인가, 세션, 캐시, 메시지 큐 |
| 7 | **데이터베이스** | 🗄️ | 데이터를 저장·조회하는 것 | 관계형, SQL, 인덱스, 트랜잭션, NoSQL, ORM |
| 8 | **서버 & 인프라 & 클라우드** | 🖧 | 코드가 실제로 돌아가는 곳 | 가상화(Proxmox/VM), 컨테이너, 리눅스 운영, 클라우드, 네트워크 장비 |
| 9 | **DevOps & 개발 도구** | 🔧 | 만들고 배포하고 지키는 과정 | Git, CI/CD, 모니터링, 로깅, IaC, 크론 |
| 10 | **보안** | 🔒 | 공격과 방어 | 암호화, 인증 공격, 웹 취약점, 네트워크 보안, 키 관리 |
| 11 | **AI / ML / LLM** | 🤖 | 학습하는 소프트웨어 | ML 기초, 딥러닝, LLM, 프롬프트/RAG, 에이전트/MCP, 서빙 |
| 12 | **의료 IT** | 🏥 | 병원·헬스케어 시스템 | 표준(HL7/FHIR/DICOM), 시스템(EMR/PACS), 규제/보안, 의료 AI |
| 13 | **소프트웨어 공학 & 협업** | 📐 | 함께 잘 만드는 방법 | 방법론, 설계 원칙, 테스트, 문서화, 아키텍처 패턴 |

### 카테고리 설계 원칙

- 용어는 **주 카테고리 1개 \+ 보조 태그 n개**. (예: JWT → 주: 백엔드 & API, 태그: 보안, 인증)  
- 대분류는 13개로 고정하고, 소분류는 태그로 유연하게.  
- "이 용어가 어디 속하는지 5초 이상 고민되면" 카테고리 설계가 잘못된 것 → 소분류를 조정.

\#\# 한 줄 정의

다른 컴퓨터의 터미널에 \*\*암호화된 통신으로 원격 접속\*\*하는 프로토콜이자 명령어.

\#\# 비유

서버 방의 \*\*열쇠 달린 뒷문\*\*. 문 앞에서 신분(비밀번호 또는 키)을 확인하고, 들어가면 그 컴퓨터 앞에 앉아 있는 것처럼 명령을 칠 수 있다.

\#\# 예시

\`\`\`bash

ssh user@10.0.0.5          \# 서버에 접속

ssh \-p 2222 user@lab.example.com   \# 포트가 22가 아닐 때

ssh-keygen \-t ed25519      \# 비밀번호 대신 쓸 키 만들기

연구실 Proxmox VM 에 붙을 때 매번 쓰는 것. 비밀번호 로그인은 끄고 키만 허용하는 게 기본 설정.

## 헷갈리기 쉬운 것

- **SSL/TLS** 와 다르다. SSH 는 원격 셸용, TLS 는 HTTPS 등 범용 암호화 통신용.  
- **Telnet** 의 암호화 버전이라고 생각하면 된다. Telnet 은 평문이라 지금은 안 쓴다.

\#\#\# 필드 규칙

| 필드 | 필수 | 규칙 |

|---|:-:|---|

| \`id\` | ✅ | 영문 소문자·숫자·하이픈. 변경 금지(링크가 깨짐) |

| \`term\` | ✅ | 가장 흔히 쓰는 표기. 약어면 약어 |

| \`aliases\` | ✅ | 한글 표기, 풀네임, 흔한 오타까지. 검색은 이 필드로 |

| \`category\` | ✅ | 13개 코드 중 하나 |

| \`tags\` | △ | 소분류. 자유 태그지만 \`tags.yml\` 에 정의된 것만 허용 |

| \`level\` | ✅ | 1\~3. 카테고리 탭에서 기초부터 정렬 |

| \`related\` | ✅ | 3\~5개 권장. 존재하지 않는 id 면 빌드 실패 |

| 본문 \`\#\# 한 줄 정의\` | ✅ | 60자 이내, 마침표 하나 |

| 본문 \`\#\# 비유\` | ✅ | 2문장 이내. 비전공자도 이해할 것 |

| 본문 \`\#\# 예시\` | ✅ | 코드·명령·문장 중 하나. 가능하면 \*\*내 환경\*\* 맥락 |

| 본문 \`\#\# 헷갈리기 쉬운 것\` | △ | 비슷한 용어와의 차이 |

빌드 시 \`scripts/validate.ts\` 가 위 규칙을 검사한다. 실패하면 배포되지 않는다. (K3, K7)

\#\#\# 설계 원칙

1\. \*\*서버 없음\*\* — 용어 300개 ≈ JSON 300KB. 전부 클라이언트에 내려 검색해도 충분히 빠르다(K4). 운영 비용 0, 보안 걱정 0\.

2\. \*\*콘텐츠와 코드 분리\*\* — \`terms/\` 만 만지면 사이트가 갱신된다. 코드 몰라도 용어 추가 가능 → 나중에 기여자 확장.

3\. \*\*검증이 곧 품질\*\* — 빌드 실패가 잘못된 카드를 막는다. 사람이 리뷰하지 않아도 최소 품질 유지.

4\. \*\*PWA 우선\*\* — 강의실에서 폰으로 열 때 오프라인이어도 뜬다.

\#\# 9\. 콘텐츠 제작 워크플로 (용어 300개를 어떻게 채우나)

이 프로젝트의 진짜 난관은 코드가 아니라 \*\*콘텐츠 300개\*\*다. 워크플로가 없으면 50개에서 멈춘다.

\#\#\# 9-1. 3단계 파이프라인

① 수집 (Inbox)  →  ② 초안 (Draft)  →  ③ 검토·발행 (Published)

\*\*① 수집\*\* — 모르는 용어를 만나는 순간 \`terms/\_inbox.md\` 에 한 줄 추가. 폰에서는 Ender Chest 에 넣고 주말에 옮긴다. 수업 노트, 연구실 슬랙, 논문에서 나온 것 전부. 이 단계는 \*\*0초 비용\*\*이어야 한다.

\*\*② 초안\*\* — 주 1회, inbox 에서 10개를 골라 초안 작성. 두 가지 방법 병행:

\- \*\*직접 쓰기\*\*: 이미 아는 용어. 15분/개.

\- \*\*LLM 초안 \+ 검토\*\*: 낯선 용어. 연구실 Qwen(또는 다른 LLM)에 6장 템플릿과 작성 가이드(10장)를 프롬프트로 주고 초안 생성 → \*\*반드시 내가 읽고 고친 뒤\*\* \`status: review\` 로. LLM 초안을 그대로 발행하지 않는 것이 규칙. 고치는 과정이 학습이다.

\*\*③ 검토·발행\*\* — 자기 검토 체크리스트(10장) 통과 → \`status: published\` → 커밋. 커밋 메시지 규칙: \`term(infra): add ssh\`.

\#\# 10\. 용어 작성 가이드라인 (품질 기준)

\#\#\# 10-1. 원칙

1\. \*\*10초 규칙\*\* — 카드 상단(정의+비유)만 읽고 "아, 그거" 가 되어야 한다.

2\. \*\*정의는 "무엇"\*\*, 비유는 "느낌", 예시는 "어떻게" — 세 역할이 겹치지 않게.

3\. \*\*내 말로\*\* — 위키백과 문장을 옮기지 않는다. 남에게 말로 설명하듯.

4\. \*\*내 환경의 예시\*\* — 가능하면 연구실·수업·내 프로젝트 맥락. "Proxmox VM 에 SSH 로 접속할 때" 가 "원격 서버에 접속할 때" 보다 기억에 남는다.

5\. \*\*차이를 적는다\*\* — 헷갈리는 쌍(세션/JWT, VM/컨테이너, 인증/인가)은 반드시 "헷갈리기 쉬운 것" 에.

6\. \*\*모르면 모른다고\*\* — 확신 없는 문장은 쓰지 않거나 \`\[확인 필요\]\` 표시. 나중에 고친다.

\#\#\# 10-2. 자기 검토 체크리스트 (발행 전)

\- \[ \] 한 줄 정의가 60자 이내이고 문장 하나인가

\- \[ \] 비유가 비전공자(부모님)에게도 통하는가

\- \[ \] 예시가 실제로 실행되거나 실제 문장인가 (복붙해서 돌아가는가)

\- \[ \] related 가 3개 이상이고 모두 존재하는 id 인가

\- \[ \] aliases 에 한글 표기와 풀네임이 있는가

\- \[ \] 비슷한 용어와의 차이를 적었는가 (해당 시)

\- \[ \] 위키백과·블로그 문장을 그대로 붙이지 않았는가

\#\#\# 10-3. 안티패턴

\- ❌ "…를 위한 프로토콜의 일종으로, 1995년 핀란드의…" (역사부터 시작)

\- ❌ 정의에 정의하려는 용어보다 어려운 용어 사용 ("SSH 는 암호화된 네트워크 프로토콜을 통해 시큐어 채널을…")

\- ❌ 비유가 더 어려움 ("SSH 는 SSL 터널과 비슷하게…")

\- ❌ 예시 없이 개념만

\- ❌ related 에 카테고리 전체를 나열

\#\# 한 줄 정의

외부 요청을 \*\*대신 받아\*\* 뒤에 있는 여러 서버로 나눠 전달하는 중간 서버.

\#\# 비유

건물 1층 \*\*안내 데스크\*\*. 손님(요청)은 데스크만 알고 오고, 데스크가 "그건 3층 B팀" 하고 안내한다. 각 팀(서버)의 방 번호(포트)는 손님이 몰라도 된다.

\#\# 예시

Proxmox 에 VM 이 3개(웹 3000, API 8000, Grafana 3001\) 있을 때, Caddy 하나만 80/443 을 열고:

app.lab.example.com   → localhost:3000 api.lab.example.com   → localhost:8000

HTTPS 인증서도 Caddy 가 한 번에 처리한다.

\#\# 헷갈리기 쉬운 것

\- \*\*포워드 프록시\*\*는 반대로 "내(클라이언트)가 밖에 나갈 때" 대신 나가주는 것. 학교 프록시가 이쪽.

\- \*\*로드 밸런서\*\*는 리버스 프록시의 한 용도(같은 서버 여러 대에 분산).

\#\# 비유

\#\# 예시

연구실 문서 200개를 임베딩해 벡터 DB 에 넣어두고, "GPU 서버 백업 정책이 뭐야?" 라고 물으면

① 질문을 임베딩 → ② 가장 비슷한 문서 3개 검색 → ③ 그 문서와 질문을 함께 Qwen 에 넣어 답 생성.

\#\# 헷갈리기 쉬운 것

\- \*\*파인튜닝\*\*은 모델 자체를 다시 학습시키는 것. RAG 는 모델은 그대로 두고 참고자료만 붙인다. 자료가 자주 바뀌면 RAG, 말투·형식을 바꾸려면 파인튜닝.

\#\# 한 줄 정의

병원 시스템끼리 환자·진료 데이터를 \*\*REST API \+ JSON\*\* 으로 주고받기 위한 국제 표준.

\#\# 비유

병원마다 다른 언어로 쓰던 진료기록을 위한 \*\*공용 서식과 우편 규격\*\*. 서식(Patient, Observation 같은 리소스)이 정해져 있어서 A 병원 데이터를 B 병원 앱이 바로 읽는다.

\#\# 예시

GET [https://hospital.example.org/fhir/Patient/12345](https://hospital.example.org/fhir/Patient/12345) → { "resourceType": "Patient", "name": \[{ "family": "김", "given": \["승원"\] }\], ... }

웹 개발자가 아는 REST 방식 그대로라서, 의료 데이터 다루는 앱을 만들 때 진입 장벽이 낮다.

\#\# 헷갈리기 쉬운 것

\- \*\*HL7 v2\*\* 는 같은 단체(HL7)의 옛 표준. 파이프(|)로 구분된 텍스트 메시지라 읽기 어렵다. FHIR 가 그 현대판.

\- \*\*DICOM\*\* 은 영상(CT/MRI) 전용 표준. FHIR 는 진료 정보 전반.
